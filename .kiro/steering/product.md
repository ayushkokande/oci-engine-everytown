# Product — Everytown OCI Assessment

## What it is
The Organizational Capacity Index (OCI) platform. A community violence intervention (CVI)
nonprofit completes a yes/no self-assessment, gets deterministic capacity scores per area, and
receives personalized, prioritized recommendations (generated by Claude on Amazon Bedrock) plus a
downloadable PDF report. Built for the AWS Breaking Barriers hackathon; handed off to Everytown Labs.

## Who it is for
- **CVI organization leaders (primary users).** Executive directors / program leads at small,
  community-rooted nonprofits with thin back-office capacity and very little spare time. They want
  practical guidance they can act on in the next weeks and months. Design every screen for them.
- **CSF program staff.** Everytown's Community Safety Fund: a two-person team supporting 140+
  grantee and alumni organizations. The manual OCI pilot (45 orgs) worked but report writing did not
  scale. They use the aggregate-only staff analytics view.
- **Everytown Labs.** Wants a forkable, open-source repo with CloudFormation they can iterate toward
  production rather than rebuild.

## Success
- 3–4 CVI organizations find the recommendations helpful.
- End-to-end run: assessment → scores → personalized recommendations → downloadable PDF.

## Product rules (non-negotiable)
- **Code computes every score; the model only writes narrative.** The LLM never computes, changes,
  re-ranks or contradicts a score, stage or priority band.
- The report is **non-evaluative**: a self-assessment snapshot, not a grade or ranking.
- **Priority bands are relative** to the gaps in one submission (percentile thirds). Always present
  them as "where to start", never as absolute severity.
- **Staff see individual assessments; organizations never see each other's.** CSF staff can open a
  named, staff-only view of each assessment (decided Nov 4, 2026). Network figures stay aggregate and
  never name another organization; no organization's results are shown to another.
- An organization can **add context and regenerate its feedback**: narrative only, never answers,
  scores, stages, gaps or bands. Earlier narrative versions are kept.
- **Synthetic data only, no PII.** Sandbox AWS account only; never Everytown's account.
- No Everytown-confidential material in the repo (it is open source).
- **Organization research reads only the org's own website** (homepage-style, AWS only). No web
  search or third-party data sources (decided Nov 4, 2026).

## Questionnaire facts
- In-scope areas (default): Planning (15), Fundraising (20), Financial Management (20),
  Monitoring, Learning & Evaluation (17) = **72 statements**. Full OCI = 143 statements / 8 areas.
- The vision doc only *confirms* Planning + Fundraising (35 statements); the spec defaulted to 4.
  The user wants to keep **4 areas**.
- **Every statement in an assessed area must be answered.** The engine treats a blank as favourable,
  which would inflate scores, so submission is blocked until complete.
- Stage spread across the 4 areas: Seeding 7, Emerging 10, Developing 17, Strengthening 27,
  Transformational 11 → **38 of 72 are advanced (stage 4–5)** practices.
- PL1 is reverse-coded (answering Yes is the gap). Polarity lives only in scoring.

## Open product decisions
1. **Reduce questionnaire fatigue without changing scores** (proposed, not built):
   - "Tick what's true" checklists grouped by stage (~20 short lists instead of 72 decisions);
     unticked items count as an explicit "no" once the user confirms the list.
   - Fast path for advanced practices: after gaps in an area's basics, show its stage 4–5
     statements as one list with a one-click "None of these yet".
   - Later: split areas across team members; pre-fill returning orgs from their last assessment.
   - Do NOT: let AI pre-fill answers (model would influence scores); cut or reword statements
     (changes the OCI instrument — Everytown's decision, ideally using pilot data).
2. Resource library: current R1–R6 entries are **placeholders** written for the MVP (general
   nonprofit practice). Replace with cleared CVI materials from Everytown.
3. Exact PDF layout to confirm with Everytown (Megan).
4. How org users are provisioned beyond mocked login.
